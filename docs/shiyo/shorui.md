# 書類の種類と出力内容（`js/app.js` の `DOC_TYPES`）

> CLAUDE.md から分けた詳細仕様。CLAUDE.md には要点だけを書き、詳細はここを更新する。

「①工事情報」の先頭で切り替える。切り替えると書類名と出力内容（チェック）が初期値になり、あとから個別に変更できる。

| 種類 | 書類名の初期値 | 出力内容の初期値 |
|---|---|---|
| 総合 `sogo` | 総合施工計画書 | 表紙・本文・工事概要・組織表ほか・添付シート。管理表なし（工事種目の選択は不要） |
| 工種別 `koshu` | 選んだ工種名（`SKUKIKKSExport.KOSHU` の16件＋その他） | 表紙・本文・管理表・対象工事種目・資料一覧・写真一覧 |
| チェックシート `check` | 工種名＋品質管理チェックシート | 選んだ工種のチェックシートだけ（施工計画書とは別ファイル。未登録の工種は空欄の様式） |
| 撮影箇所 `satsuei` | 工種名＋工事写真の撮影箇所 | 選んだ工種の撮影箇所だけ（別ファイル。作成例に無い工種は撮影対象表の全行） |
| 施工チェック `seko` | 電気設備工事施工チェックシート | 施工チェックシート（表紙・使用にあたって・選んだ工事）と申請手続一覧表。品質管理チェックシートとは全く別の書類 |
| 施工計画書のみ `kan` | 施工計画書 | 表紙・工事概要・組織表ほか・管理表・各一覧（簡略的な工事向けに1冊にまとめる） |

- 工種別は1工種ずつ作成する（工種を切り替えて出力を繰り返す）。工種別を選んだとき・工種を切り替えたときは、
  管理表の ⑵〜⑼ の選択をその工種の項目に置き換える（`js/app.js` の `KOSHU_ITEMS`。⑴ は変えない。あとから変更できる）。
  対応の無い工種（検査・試運転の計画書、その他）は選択を変えない
- 未保存（初回・旧版）のときは `kan`。旧版で保存済みのチェックは変えず、未設定の項目だけ初期値にする
- 選択中の種類をもう一度押しても初期値には戻さない（入力済みの書類名を消さないため）
- 「品質管理チェックシート」「工事写真の撮影箇所」「機器搬入計画書ほか」のどれかにチェックがあるときは、
  種類にかかわらず「工種」欄を表示する。
  総合・施工計画書のみで工種を変えても、書類名と出力内容は変えない
- チェックシートは作成例の別添1を工種ごとに `data/checklist.js` へ登録する（(1)〜(12)）。総合試運転計画書は
  `js/export/shiunten.js` の `SHIUN` のチェックリスト7枚を使う。作成例にチェックシートが無い工種は空欄の様式。
  煙感知器の「0.6m以下」は本文に合わせ「以内」にしている（K-57）。
- 工事写真の撮影箇所（別添2）は、作成例の別添2 の行を工種ごとに `data/satsuei.js` へ登録している。
  元の表は巻末資料の撮影対象表（電気設備工事編）。詳細は `docs/honsho/04_3_satsuei_denki.md` の「アプリへの反映」

- 「機器搬入計画書・体制表・ワイヤロープの選定ほか」は「③出力内容」のチェックで出す（初期値は全種類オフ。チェック時は「工種」欄を表示）。
  搬入計画書は雛形として共通で残せる欄だけ記入し、機器・現場ごとに変わる欄は項目だけ残して白紙にする。
  搬入経路・揚重計画ほか（③〜⑥）は見出しだけの1シート。ワイヤロープの選定は条件の欄を Excel で書き換えると再計算される。
  据付け施工要領は本文だけ（図は Excel で作成）、アンカーの施工要領は作成例 p.439 の全文。
  記入範囲の詳細は `docs/honsho/03_3_2_08_cubicle.md` の「アプリへの反映」。
  工種が (9) 自家発電装置・(10) 太陽光発電装置のときの違い（㈣品目の行、運搬方法の項目数、体制表ほか。
  太陽光は搬入経路・ワイヤロープ・アンカーのシートを出さず、据付け施工要領はアレイの取付け方法ほか）は
  `03_3_2_09_jikahatsu.md`・`03_3_2_10_taiyoko.md`

- 「本文」は作成例の文章を1シートに出す。工種別のときは「工種」の施工計画書、それ以外は総合施工計画書の本文。
  図は置き場所の注記、別シートにある図表は「別シート「○○」を参照」にする。作成例の無い「その他」は出さない。
  `data/honbun.js` は本文を出力するとき（チェックしたとき）だけ読み込む（`SKUKIKKSExport.loadHonbun`）。
  原本から表記を変えたもの（K-44・K-53・K-73・K-89）は `tools/build_honbun.py` の `FIX`、自動で作れない項は `OVERRIDE`。
  変換は記録用の言葉が本文に残ると失敗する。除いた行は `--dropped` で確認する
- 「使用前自主検査の検査項目」も「③出力内容」のチェックで出す（初期値は全種類オフ。工種には連動しない）。
  作成例 (14) の ⑥ 自主検査の方法及び判定基準を、検査項目ごとに1シートにする。B種接地抵抗許容値は再計算でき、
  絶縁耐力試験の手順フローはセルの罫線と矢印の文字で描く。別添1 工程表（8〜17時の雛形）・別添2 管理台帳も付ける。
  詳細は `docs/honsho/03_3_2_14_jishu.md` の「アプリへの反映」
- 「総合試運転のフローとチェックリスト」も同じ（初期値オフ）。作成例 (15) の試験ごとに1シートで、上にフロー、下にチェックリスト。
  詳細は `docs/honsho/03_3_2_15_shiunten.md`
- 「総合試運転報告書の表」も同じ（初期値オフ）。作成例 (16) の確認結果の表を1つ1シートで出す（指摘事項・所見の欄つき）。
  詳細は `docs/honsho/03_3_2_16_hokoku.md`

- 「電気設備工事施工チェックシート」（書籍：公共建築協会 令和7年版）は「③出力内容」のチェックで出す（施工チェック `seko` 以外は初期値オフ）。
  チェックすると下に工事（11章：一般共通事項／配管／配線／機器取付け／接地／雷保護／架空配線／地中配線／受変電等／中央監視制御／医療関係）
  の選択欄が出る（初期値はすべて選択。`state.sekoChap`）。工種には連動しない。
  表紙の工事名称・工事場所・工期・受注者は①工事情報の入力値を入れる（建築物名称・住所・電話・変更工期は空欄）。
  書籍の白紙・空白の記入用紙は出さない（SC-25）。丸囲みの「検」「立」は「(検)」「(立)」と書く（SC-23）
- 「主な官公署その他への申請手続一覧表」（同書の参考資料）も「③出力内容」のチェックで出す。〈電事則〉別表第二を別シートで付ける
- データは `docs/sekocheck/*.md` から `tools/build_sekocheck.py` で `data/sekocheck.js` を作る。原本から変えた表記は
  `docs/sekocheck/00_kakunin.md` の SC 番号（SC-02・08・10・11・13・28〜31）
